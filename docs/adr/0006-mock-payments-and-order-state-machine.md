# ADR 0006: Mock Payment Provider и конечный автомат заказа

- Статус: принят
- Дата: 2026-08-12

## Контекст

Checkout создаёт заказ и активные складские резервы, но не может держать транзакцию PostgreSQL
открытой во время обращения к внешнему платёжному провайдеру. Ответ провайдера приходит позже,
может повторяться, запаздывать или быть подделан. Одновременно клиент может отменить заказ, а
менеджер — оформить возврат. Без явного автомата эти действия способны дважды списать товар или
вернуть резерв после успешной продажи.

## Решение

Этап использует Mock Payment Provider без сети и банковских данных. Клиент создаёт одну платёжную
сессию только для собственного заказа в состоянии `pending_payment`. `Idempotency-Key`, advisory
lock и ограничения PostgreSQL защищают как повтор HTTP-запроса, так и параллельное первое
создание.

Webhook подписывается HMAC-SHA256 по `<unix_timestamp>.<raw_body>`. Сервис:

1. отклоняет timestamp вне настроенного временного окна;
2. сравнивает подпись constant-time функцией;
3. проверяет строгую JSON-схему, сумму и валюту;
4. сериализует уникальный ID события advisory lock;
5. хранит SHA-256 тела, чтобы отличить точный replay от подмены события;
6. блокирует платёж, заказ и резервы перед изменением;
7. сохраняет все изменения одним commit.

Разрешены только переходы:

- `pending_payment -> paid | payment_failed | cancelled`;
- `paid -> refunded`.

Успех платежа погашает резерв и уменьшает `reserved` вместе с `on_hand`. Ошибка или отмена
освобождает резерв и уменьшает только `reserved`. Refund всегда полный, идемпотентный и не
возвращает товар на склад автоматически.

## Последствия

- точные повторы сессии, webhook и refund безопасны;
- позднее несовместимое событие фиксируется как `ignored`, но не меняет терминальное состояние;
- повтор event ID с другим телом отклоняется как конфликт;
- клиент видит только свои платежи, менеджер и администратор — все;
- возврат денег и физический возврат товара остаются разными бизнес-операциями;
- реальные PSP, частичные refunds, Outbox и асинхронная доставка событий остаются отдельными
  этапами.
