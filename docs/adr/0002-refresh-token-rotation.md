# ADR 0002: ротация refresh-токенов через серверные сессии

- Статус: принято
- Дата: 2026-08-10

## Контекст

Полностью stateless refresh JWT нельзя отозвать при выходе, компрометации или отключении пользователя до окончания срока действия. Хранение открытого refresh-токена в базе, в свою очередь, превращает утечку базы в готовый набор действующих учётных данных. Параллельные refresh-запросы также могут случайно выпустить несколько новых токенов из одного старого.

## Решение

- access JWT действует 15 минут и не хранится в базе;
- refresh JWT связан с записью `auth_sessions` сроком до 30 дней;
- PostgreSQL хранит SHA-256-хэш refresh-токена;
- каждый refresh блокирует сессию `SELECT FOR UPDATE`, выпускает новую пару и атомарно заменяет хэш;
- несовпадение хэша считается повторным использованием старого токена и отзывает сессию;
- logout идемпотентно устанавливает `revoked_at`;
- JWT принимается только с явно заданным алгоритмом, issuer и audience.

## Последствия

Плюсы:

- refresh-токен можно отозвать немедленно;
- повторное использование украденной старой версии обнаруживается;
- один старый токен нельзя успешно обновить дважды параллельно;
- открытые refresh-токены не хранятся в базе.

Ограничения:

- refresh требует обращения к PostgreSQL;
- access JWT остаётся действительным до 15 минут, но каждый защищённый запрос всё равно проверяет актуальные `is_active` и `role` пользователя;
- при обнаружении повторного использования пользователю потребуется войти заново.
