# ADR 0010: Next.js-интерфейс и same-origin API proxy

- Статус: принято
- Дата: 2026-08-20

## Контекст

OrderFlow достиг завершённого backend-сценария, но для демонстрации требовал интерфейс покупателя и
операционной команды. Прямой вызов FastAPI из браузера потребовал бы отдельной CORS-политики и
публикации адреса API, а дублирование бизнес-правил во frontend ослабило бы существующие гарантии.

## Решение

Разместить в монорепозитории отдельное приложение Next.js 16 с React 19 и TypeScript. Браузер
обращается к относительному `/api/v1`, а серверный catch-all Route Handler проксирует запрос во
внутренний FastAPI URL. UI использует только публичные API-контракты, строит навигацию по роли, но
оставляет окончательную авторизацию бэкенду.

Для добавления товара в корзину предоставить публичный read-only endpoint доступности активного
товара по активным складам. Он возвращает только идентификатор, название, код и доступное
количество и не открывает складские операции.

Access и refresh-токены хранятся в `sessionStorage`. Один общий refresh promise предотвращает
параллельную повторную ротацию после нескольких `401`; запрос повторяется не более одного раза.

## Последствия

- пользователь открывает один origin, а Docker-связь UI–API остаётся внутренней;
- интерфейс разворачивается и проверяется независимо от Python-приложения;
- RBAC и бизнес-инварианты остаются в FastAPI;
- сессия очищается при закрытии вкладки, но, как и любое браузерное token storage, требует строгой
  защиты от XSS;
- реальный эквайринг и полноценная административная панель остаются за границами MVP.
